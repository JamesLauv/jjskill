# 多源资料逻辑重构

把散乱的多格式资料，整理成清晰、统一、可直接使用的结构化逻辑产物。

## 适用场景

- 客户给了一堆截图、PPT、Word，要整理成流程图
- 多份文档描述同一个业务流程，需要合并去重
- 收到的资料格式混乱（图片+文档+表格），需要统一整理
- 已有输出需要根据新资料增量更新
- 售前/产品/项目交付中的资料整理工作

## 不适用场景

- 只有一份文档，需要做决策分析 → 走 `jjskill-doc-to-decision-artifacts`
- 需要深度交互共创、组织沟通策略 → 走 `jjskill-doc-to-decision-artifacts`
- 纯粹的文件格式转换（如pdf转word） → 不需要skill

## 默认工作流

### Phase 1: 输入识别与内容提取

收到文件后，按扩展名自动选择提取方式：

| 格式 | 提取方式 | 工具 |
|---|---|---|
| `.png/.jpg/.jpeg/.gif/.bmp` | 视觉分析，识别图中文字、结构、流程 | 内置视觉能力 |
| `.pptx` | 提取幻灯片文本、表格、备注 | `scripts/extract_pptx.py` |
| `.docx` | 提取段落文本、表格内容 | `scripts/extract_docx.py` |
| `.xlsx/.xls` | 读取各Sheet数据 | openpyxl |
| `.pdf` | 读取文本内容 | Read工具（pages参数） |
| `.md/.txt` | 直接读取 | Read工具 |
| `.drawio` | 解析XML结构 | 直接读取XML |
| `.html` | 提取文本和结构 | WebFetch或Read |

提取时保留原始信息的层级结构（标题、段落、表格行列关系），不要打平成纯文本。

### Phase 2: 跨源融合

多份资料往往描述同一件事的不同侧面，需要融合：

1. **识别重叠** — 不同文件中描述相同实体/流程/规则的内容，标记为重叠
2. **识别差异** — 同一实体在不同文件中的描述不一致时，标注差异并保留两种说法
3. **识别互补** — 不同文件各自覆盖整体的不同部分，合并为完整视图
4. **建立统一框架** — 用一致的分类维度组织所有信息（如按客户类型、业务场景、处理方式等）

融合原则：
- 宁可多保留，不要轻易丢弃信息
- 差异处标注来源，让用户决定取舍
- 互补部分合并后检查逻辑完整性

### Phase 3: 逻辑重构

把融合后的信息重构成清晰的逻辑结构：

1. **确定分类维度** — 找到最核心的分类轴（如客户类型、业务场景、时间阶段）
2. **建立层级** — 大类 → 小类 → 场景 → 处理方式 → 系统约束
3. **标注差异** — 不同分类下的处理差异要显性化
4. **补充约束** — 从资料中提取的系统约束、业务规则、特殊说明要关联到对应节点

重构质量标准：
- 任何人看到输出都能快速理解全貌
- 同一个事实不会在不同位置重复出现（除非有意识的交叉引用）
- 分类维度清晰，不会出现"某个场景不知道放哪个分类"的情况
- 差异和特殊规则有显性标注

### Phase 4: 确认与输出

如果用户没有指定输出格式，按用途建议：

| 用途 | 推荐格式 | 理由 |
|---|---|---|
| 逻辑讨论/流程对齐 | drawio | 可拖拽编辑，适合会议讨论 |
| 方案汇报/快速浏览 | html | 视觉化，可交互，无需安装 |
| 正式文档/存档 | svg | 矢量图，清晰可缩放 |
| 数据化管理/筛选 | xlsx | 多Sheet，支持筛选排序 |
| 全部都要 | 全部 | 并行生成所有格式 |

用户指定格式后直接输出，不要反复确认。

### Phase 5: 增量补充（可选）

当用户后续提供额外资料时：

1. 读取新资料，提取增量内容
2. 识别增量内容与已有输出的关联（对应哪个分类/节点）
3. 合并到已有结构中（新增节点、补充规则、标注差异）
4. 另存为新版本，保留原文件

## 各格式输出规格

详细规格见 `references/output_formats.md`。关键要求：

### drawio
- 使用泳道（swimlane）组织大类
- 节点按颜色区分类型（原因/条件/处理/结果/二期）
- 连线表示流程走向
- 底部图例说明颜色含义

### svg
- 左右分栏布局（如按客户类型）
- 颜色编码与drawio一致
- 自包含，不依赖外部资源

### html
- 单文件，Tailwind CSS CDN
- 卡片式布局，左右分栏
- 响应式，支持移动端
- 图例区和特殊说明区

### xlsx
- 多Sheet结构：总览 + 分类视图 + 对比视图 + 规则补充
- 表头冻结，支持筛选
- 颜色编码区分数据类型
- 合并同类单元格减少视觉噪音

## 脚本使用

### PPTX提取

```bash
python <skill-path>/scripts/extract_pptx.py <file.pptx>
```

输出：每页幻灯片的文本内容和表格数据（JSON格式）。

### DOCX提取

```bash
python <skill-path>/scripts/extract_docx.py <file.docx>
```

输出：段落文本（含层级标记）和表格数据（JSON格式）。

### Excel生成

```bash
python <skill-path>/scripts/gen_excel.py <input.json> <output.xlsx>
```

接受结构化JSON输入，生成带样式的多Sheet Excel。JSON格式见脚本内注释。

## 文件命名与输出规则

- 文件名加 `-cc` 后缀标识来源
- 保存到用户指定目录
- 多格式输出时统一文件名前缀，仅扩展名不同
- 增量补充时文件名加版本号（如 `-v2`、`-含规则补充`）
- 最终回复列出所有输出文件及用途说明

## 避免事项

- 不要把多份资料简单拼接，要做融合去重
- 不要丢弃"看起来不重要"的信息，售前资料的细节往往是关键
- 不要只输出一种格式就结束，除非用户明确只要一种
- 不要把差异信息强行统一，保留原始分歧让用户判断
- 不要在融合时引入资料中没有的信息
